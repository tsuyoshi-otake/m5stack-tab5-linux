# v0.7.1 hardware validation (2026-11-25)

Board: M5Stack Tab5 (ST7121 panel, no battery pack, A164 keyboard not
attached), P4 USB Serial/JTAG on COM13.  Only the P4 flash was written; the
C6 was not touched (it already ran ESP-Hosted-NG 1.0.6).  The board's boot
drive was kept, so it booted with its own settings: station mode on a
2.4 GHz WPA2 home router, `text_color=amber`, a bonded BLE keyboard.

v0.7.1 is `main` at a378170, one commit after v0.7.0: the boot shim reads
`text_color=` from `config.txt` and writes the preset into the kernel's VT
palette defaults (`vt.default_red/_grn/_blu=` in the bootargs), so the
panel shows the boot log in that colour from the first kernel line instead
of in the stock colours until `S07textcolor` runs; `S07textcolor` and
`m5-config` keep those defaults in step with a live change.  The release
build sets `NOMMU_POOL_BESTFIT=1`, `NOMMU_USER_RESERVE=1` and
`NOMMU_SYSTEM_MARK=1` through `linux/release-build.sh` (#8).

## The panel

The webcam that watches the panel had its view blocked during this run, so
the panel was not photographed on the release image.  It was photographed
on a local build of the same commit (`build-canon.sh tab5` at a378170, the
same `esp32p4-tab5.dtb` and `boot.img` hashes as above, the boot shim
compiled from the same sources), flashed the same way and rebooted the
same way: the boot shim's black screen, then the first frame with kernel
text already amber -- every line of the log replayed when fbcon takes the
panel, and the lines after it, through to the shell.  On that build a
live switch to white showed the stock colours (red, green and blue text in
their own colours), a switch back to amber followed by `ESC ] R` stayed
amber, and VT 2, brought forward with `ESC [ 12 ; 2 ]`, showed the kernel
messages in amber.

## Not covered

- The 16 MB image was not flashed, so a blank-drive first boot (new
  credentials, Wi-Fi QR) was not repeated on this image; it would have
  replaced the board's settings and Bluetooth bond.  On a blank drive there
  is no `text_color=`, and the boot shim leaves the stock palette.
- The touch menu's text colour picker was not driven on the board for this
  release; its palette restore is covered by `test-m3-lab-m5-config.sh`.
- The SoftAP <-> station switch, touch, typing, sound, the camera with
  `camera=on`, a cold power-on and `poweroff` were not repeated on this
  image; v0.7.1 changes only the boot shim's palette patch, the DTS
  bootargs and the text colour scripts, and those were checked on v0.7.0
  (`v0.7.0-hardware-validation-2026-11-25.md`) and the issues the README
  Status table names.
- `flash-candidate.ps1` was started from a PowerShell prompt-style
  `-Command "& .\flash-candidate.ps1 ..."` with `-PythonPath` naming the
  Python that has esptool (on this PC `python` is the Windows Store stub).
  Started as `powershell -File flash-candidate.ps1` (Windows PowerShell
  5.1) it still leaves `-ArtifactsDirectory` empty, as recorded for v0.7.0.
