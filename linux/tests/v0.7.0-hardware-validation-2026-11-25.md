# v0.7.0 hardware validation (2026-11-25)

Board: M5Stack Tab5 (ST7121 panel, no battery pack, A164 keyboard not
attached), P4 USB Serial/JTAG on COM13.  Only the P4 flash was written; the
C6 was not touched (it already ran ESP-Hosted-NG 1.0.6).  The board's boot
drive was kept, so it booted with its own settings: station mode on a
2.4 GHz WPA2 home router, `text_color=amber`, a bonded BLE keyboard.

v0.7.0 is `main` at 41668e8, 211 commits after v0.6.0: the hardware rows of
the README Status table that were added after v0.6.0 (I/O expanders, power
off and battery #31, RTC #28, IMU #26, INA226 #27, USB-A host #30, microSD
#29, Bluetooth #34, EXT rails #35, Deep Sleep #37, speaker and microphones
#24, the one-shot camera driver #25/#44), the `m5-config` settings menu with
its touch mode (#42), the BLE keyboard (#41), the boot FAT guard (#43), the
C6 link watch and the charger decision (#41), kernel messages on VT 2 and
the self-reloading scan-out (#42), the ttyGS1 recommit (#45) and the
ESP-Hosted command matching that makes a live SoftAP -> station switch work
(`0049`).  The release build sets `NOMMU_POOL_BESTFIT=1`,
`NOMMU_USER_RESERVE=1` and `NOMMU_SYSTEM_MARK=1` through
`linux/release-build.sh` (#8).

## Not covered

- The 16 MB image was not flashed, so a blank-drive first boot (new
  credentials, Wi-Fi QR) was not repeated on this image; it would have
  replaced the board's settings and Bluetooth bond.
- No client joined the SoftAP during the live switch (the board's SoftAP
  was checked with `iw`, its address and `udhcpd`); SSH was checked over the
  router instead.
- Touch, typing, the BLE keyboard (it was asleep, not connected), sound,
  the camera with `camera=on`, a cold power-on and `poweroff` were not
  repeated on this image; they were checked on branch builds in the issues
  the README Status table names.
- `flash-candidate.ps1` started as `powershell -File flash-candidate.ps1`
  (Windows PowerShell 5.1) stops with "Cannot bind argument to parameter
  'LiteralPath' because it is an empty string": in an advanced script the
  `$PSScriptRoot` default of `-ArtifactsDirectory` is empty there.  Run from
  a PowerShell prompt as the README says (`.\flash-candidate.ps1 ...`), from
  `pwsh`, or with `-ArtifactsDirectory <folder>` it works; the write above
  was made from a prompt-style invocation.
